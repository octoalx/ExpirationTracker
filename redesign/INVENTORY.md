# Инвентарь экранов ExpirationTracker (для дизайнера)

Опись существующих экранов по коду. Ничего в коде не менялось; все цитаты — дословные строки из интерфейса. Инварианты из AGENTS.md / PRODUCT.md / DESIGN.md учтены: интерфейс русский, телефон — главное устройство (на мобильных список карточек, на десктопе таблица), статусы ACTIVE/ARCHIVED/DEFECT («Активен» / «Архив» / «Брак»), сканирование штрих-кода — первичный сценарий, без тёмной темы и фотографий в списке.

Обозначения ролей: любой авторизованный сотрудник отдела; MANAGER — руководитель отдела; ADMIN — администратор платформы (таблиц отделов не видит). Роуты защищены сессией NextAuth; неавторизованных отправляет на `/auth/signin`.

---

## 0. Общая оболочка (все экраны кроме /auth/*)

Файлы: `src/pages/_app.tsx`, `src/components/Layout.tsx`, `src/components/MobileHeader.tsx`.

- **Десктоп (≥md):** фиксированный левый сайдбар 224px: бренд «ExpiTrack», навигация «Товары» (/dashboard), «Обход» (/store), «Статистика» (/stats), «Настройки» (/settings), у ADMIN дополнительно «Админ» (/admin); внизу имя пользователя и кнопка «Выйти».
- **Мобильный:** верхняя шапка `MobileHeader` — бренд-ссылка на /dashboard + строка профиля (кружок с иконкой, имя/email, иконка настроек, шеврон → /settings); нижняя таб-навигация «phone-nav» с теми же 4–5 пунктами (иконка + подпись, активная — синяя с полоской).
- Переходы между страницами — fade/slide 0.25s (framer-motion), `reducedMotion` учитывается; всплывающие уведомления — toast (react-hot-toast).
- Кнопка «Наверх» (BackToTop).

## 1. /dashboard — «Товары» (главный экран)

Файл: `src/pages/dashboard.tsx` (+ `ProductTableEnhanced.tsx`, `MobileProductList.tsx`, формы, модалки). Видят: сотрудники отдела; ADMIN без отдела список не получает. Назначение: реестр записей о товарах — поиск, фильтры, добавление, редактирование, смена статусов, удаление.

### Блоки
1. **Шапка страницы:** заголовок «Товары» + счётчик записей в серой плашке; справа кнопка «Добавить» (outline, + иконка).
2. **Быстрая статистика (только десктоп):** строка «Всего: N · Скоро истекает: N · Просрочено: N».
3. **Панель поиска/сканера:** поле поиска (плейсхолдер «Название или штрих-код», иконка лупы, крестик очистки) + крупная синяя кнопка «Сканировать товар» (иконка штрих-кода; на мобильном на всю ширину).
4. **Баннер результата скана** (когда отсканировано): «Штрих-код **N** · Найдено: N» + ссылка-кнопка «Все товары» (сброс).
5. **Фильтры:** чипы-вкладки «Все» / «Скоро истекает» / «Просрочено»; ниже селект состояния «Все состояния» / «Активные» / «Архив» / «Брак»; на мобильном ещё селект сортировки («Сначала новые» / «Скорее истекают» / «Позже истекают»); кнопка «Сбросить» (скрыта на мобильном).
6. **Панель массовых действий** (только десктоп, при выделении): «Выбрано: N», кнопки «В Активные», «В Архив», «В Брак», «Печать», «Удалить» (если canDelete), «Отмена».
7. **Список:** на мобильном — карточки (см. 1a), на десктопе — таблица (см. 1b).
8. **Пагинация:** стрелки + номера страниц (до 5), «На странице:» select 10/25/50/100.
9. **Модалки:** сканер, добавление, редактирование, импорт Excel (ниже).

### 1a. Мобильный список (карточки, `MobileProductList.tsx`)
Каждая карточка — раскрывающаяся строка: слева название (bold), штрих-код с иконкой, количество («N шт.» или «Количество не указано»), бейдж статуса («Активен» синий / «Архив» серый / «Брак» красный); справа фиксированная колонка 112px: дата («дд.мм.гггг» или пусто) и маркер срочности с точкой: «Просрочен» / «Срочно» / «Внимание» / «В норме» / «сегодня» / «Срок не указан», под ним «N дн.»; шеврон разворота. Заголовок-колонка «Товар | Годен до».
- Тап по карточке — раскрытие: 4 кнопки-плитки «Изменить», «Брак», «Активные», «Архив» (текущий статус подсвечен залитым цветом и не нажимается).
- Свайп влево — красный слой с кнопкой «Удалить»; удаление отложенное (6 с) с toast «Товар удалён» и кнопкой «Отменить».

### 1b. Десктопная таблица (`ProductTableEnhanced.tsx`)
Колонки: чекбокс (выделить все/строку), «Название», «Кол-во», «Штрих-код», «Срок годности», «Статус», «Действия». Сортировка кликом по заголовку (стрелки ↑/↓/↕) по всем колонкам.
- «Срок годности»: бейдж с иконкой и текстом «Просрочен» / «Срочно · N дн.» / «Внимание · N дн.» / «Осталось N дн.», справа мелко сама дата; если даты нет — «Срок не указан».
- «Статус»: пилюля «Активен» / «Архив» / «Брак».
- «Действия»: 5 иконочных кнопок (карандаш «Редактировать», галочка «В Активные», архив «В Архив», треугольник «В Брак», корзина «Удалить» — последняя только при canDelete); активный статус кнопки подсвечен.
- Инлайн-редактирование двойным кликом по названию/количеству/штрих-коду/сроку; одиночный клик копирует значение в буфер с тултипом «Скопировано».
- Подвал: «Выделено X из Y» и «Всего: N товаров».

### Действия
- Сканирование: модалка «Сканировать товар» с описанием «Найдём записи по штрих-коду. Если товара нет в списке, откроем добавление.»; сразу открывается камера (`BarcodeCamera`: видео, статус «Запускаем камеру…» / «Наведите заднюю камеру на штрих-код. Держите телефон неподвижно.», ошибки доступа/HTTPS, кнопка «Закрыть камеру»); ссылка «Открыть камеру» если камера закрыта; поле «Или введите штрих-код» (8–14 цифр) и кнопка «Найти товар» / «Проверяем товары…». Найдено — фильтр по коду + toast «Товар найден. Показаны все записи по штрих-коду.»; не найдено — открывается модалка добавления с подставленным кодом.
- Добавление: модалка «Добавить товар» + сворачиваемый блок «Добавить несколько товаров из файла» с кнопкой «Импорт из Excel». Форма (`AddProductForm`): поле «Штрих-код» (с кнопкой-сканером и ссылкой «Найти название в каталоге» / «Поиск названия…»), «Название товара» (плейсхолдер «Например: Герметик силиконовый»), сегмент-переключатель «Годен до | Изготовлен»; при «Годен до» — «Дата окончания срока (необязательно)»; при «Изготовлен» — «Дата изготовления», «Срок хранения» + единицы «Дни | Недели | Месяцы» и превью «Годен до: дд.мм.гггг» (или «Укажите дату и срок»); «Количество (необязательно)»; кнопка «Сохранить товар» / «Сохраняем…». Сообщения каталога: «Название найдено. Укажите срок годности.», «В каталоге нет названия. Введите его вручную.»
- Импорт Excel (`ImportExcelModal`): заголовок «Импорт из Excel», описание форматов; drop-зона «Перетащите файл сюда или нажмите для выбора», «Поддерживаются .xls и .xlsx»; предпросмотр-таблица (Штрихкод / Наименование / Кол-во / Годен до, удаление строк), «Тип: Инвентаризация/Каталог товаров/Простая таблица», «Найдено товаров: N», предупреждение «Строк с ошибкой: N — они не загрузятся»; кнопка «Импортировать N товаров»; успех: «Успешно импортировано: N товаров», «Уже были в таблице: N», «Не загружено из-за ошибок: N» + список причин.
- Редактирование: модалка «Редактировать товар» (`EditProductForm`): Штрих-код, Название продукта, Количество (опционально), сегмент «Годен до | Изготовлен» (те же поля, что при добавлении), кнопки «Отмена» и «Сохранить» / «Сохранение...». Также открывается по ссылке `/dashboard?edit=ID` (из Обхода и Статистики).
- Удаление: одиночное (иконка/свайп), массовое; на мобильном — с отменой, на десктопе — сразу.
- Массовые смены статусов и «Печать» (реально — экспорт выделенных записей в Excel).

### Состояния
- Загрузка: «Загружаем товары…» со спиннером.
- Ошибка загрузки: красный блок с текстом ошибки и кнопкой «Повторить» (или текст сервера про отсутствие отдела).
- Пусто (после фильтров/вообще): иконка коробки, «Товары не найдены», «Измените фильтры или добавьте товар, чтобы начать.», кнопка «Добавить товар»; в таблице свой пустой блок «Товары не найдены» / «Измените фильтры или добавьте товары».
- Пусто при выделении в таблице: «Товары не найдены» внутри таблицы.
- Автообновление списка каждые 10 с (без индикатора).
- Список скрывается на время скан-поиска; ошибки скана — в модалке («Введите штрих-код из 8–14 цифр.» и др.).

## 2. /store — «Отдел / Обход»

Файлы: `src/pages/store.tsx`, `src/components/store/Inspection.tsx`, `src/components/store/StoreTeam.tsx`. Видят: сотрудники отдела (обход + команда), MANAGER дополнительно управляет командой; ADMIN без отдела — только объяснение; ADMIN, временно вошедший в отдел, — предупреждение. Назначение: ежедневный обход полок и управление отделом.

### Блоки
- Заголовок «Отдел · {имя отдела}» (или просто «Отдел»); справа ссылка «Подключить Telegram» → /settings.
- Переключатель «Обход | Команда» (кнопки, виден только при наличии отдела).
- Предупреждение поддержки: «Вы вошли в отдел как поддержка: ваши действия записываются в журнал. Выход — в разделе «Отделы» админ-панели.»
- Состояние без отдела (сотрудник): «Вы пока не входите в отдел. Руководитель отдела создаёт сотрудникам учётные записи сам — обратитесь к нему.»
- Состояние ADMIN: «Администратор сервиса не состоит в отделах и не видит их таблицы. Отделы, руководители и временный доступ — в админ-панели.» + ссылка «Открыть раздел «Отделы»».

### Вкладка «Обход» (`Inspection.tsx`)
- Карточка-сводка: «Обход полок», строка «Просрочено: N · Срочно: N · Внимание: N», «Сегодня проверено: N · Завершено: N. Проверка наличия сохраняет риск до решения.», режимы-кнопки: «По риску», «Не найдены (N)», «Без срока (N)».
- Очередь карточек-записей: название; строка «{штрих-код} · Срок: дд.мм.гггг · Количество: N»; статус срока («Просрочено на N дн.» красным / «Истекает сегодня» / «До окончания: N дн.» / «Нужно уточнить срок на упаковке» / «· не найден на полке»); «Проверен: {имя} · дата/время (Минск)»; claim: «Проверяет: {имя}. Закреплено до ЧЧ:ММ.»
- Действия по карточке: «Взять на проверку»; когда проверка у тебя — кнопки результата: «Проверен, ещё на полке», «Не найден», «Полностью продан», «Снят с полки», «Брак» (последние три — с подтверждением: «{результат}: {название}, срок …? Будет обработана вся запись.» + «Подтвердить» / «Отмена»), «Освободить», ссылка «Исправить данные» → /dashboard?edit=ID.
- Пусто: «В этой очереди нет записей. Актуальные риски остаются видны в таблице.»
- Автообновление каждые 10 с.

### Вкладка «Команда» (`StoreTeam.tsx`, вариант page)
- Заголовок «Команда · {отдел}», подпись «Таблица у отдела одна, её ведут все сотрудники. Учётные записи сотрудников создаёт и отзывает руководитель.»
- Список участников: «{имя} · это вы», «{email} · Руководитель отдела / Сотрудник».
- MANAGER: форма переименования («Название отдела» + «Переименовать отдел»), у каждого сотрудника кнопки «Сбросить пароль» (через window.prompt) и «Отозвать доступ» (window.confirm), форма «Новый сотрудник»: Имя, Email (логин), Пароль + «Создать сотрудника»; примечание «Пароль показывается один раз — передайте его сотруднику лично. Сменить пароль сотрудник может сам в настройках.»
- Пороги (форма «Общие пороги контроля»): «Срочно, дней», «Внимание, дней» + «Сохранить пороги»; у сотрудника поля заблокированы, подпись «Пороги меняет руководитель отдела.»
- Сообщения об успехе: «Сохранено.», «Пароль изменён. Передайте сотруднику новый пароль.», «Сотрудник создан. Передайте ему email и пароль.», «Доступ отозван.», «Название отдела сохранено.», «Пороги сохранены.»

### Состояния

## 3. /stats — «Статистика»

Файл: `src/pages/stats.tsx`. Видят: все авторизованные. Назначение: дневной обзор рисков и состава базы. Заголовок «Статистика», подпись «Сроки активных товаров и задачи на сегодня».

### Блоки
1. **Карточки-показатели (4):** кнопки-фильтры «Просрочено» (красная) и «Скоро истекает» (янтарная, urgent+warning) с большими числами; плитка «В норме» (число); плитка-ссылка «Без срока» (якорь на секцию ниже).
2. **«Требуют внимания N»:** сегмент-фильтр «Все | Просрочено | Близкий срок»; список записей-ссылок (название bold, штрих-код, шеврон) с плашкой «дд.мм.гггг · Просрочено: N дн. / Истекает сегодня / Осталось: N дн.»; тап открывает редактирование записи на /dashboard. Пусто: «Нет активных товаров для проверки.» либо «В этой группе нет товаров, требующих внимания.» Сноска: «Оценка по N активным записям. Близкий срок — до N дней включительно; срочный — до N. Архив и брак исключены из проверки сроков.»
3. **«Срок не указан N»:** пояснение «У этих активных товаров нельзя оценить остаток срока. Откройте запись, если дата уже известна.»; записи со ссылкой-действием «Указать срок»; пусто: «Нет активных товаров без указанного срока.»
4. **«Состав базы»:** dl-сетка 2×2/4: «Всего записей», «Активные», «Архив», «Брак».
5. **Сворачиваемый блок «Активность и уведомления»:** «Добавлено за 30 дней: N», «Записей в журнале email: N. Это количество попыток, а не подтверждение доставки.», «Последняя запись: дд.мм.гггг ЧЧ:ММ · статус», ссылка «Настроить уведомления» → /settings.
6. **Кнопка «Обновить данные» / «Обновление…»** (внизу).

### Состояния
- Загрузка: два серых скелетона (pulse).
- Ошибка: «Не удалось загрузить данные» + «Попробуйте обновить статистику ещё раз.» + «Повторить».
- Пустая база: «Начните с первого товара», «Добавьте товар и его срок — здесь появятся задачи для проверки.», кнопка-ссылка «Добавить товар» → /dashboard.

## 4. /settings — «Настройки»

Файл: `src/pages/settings.tsx` (+ `TelegramConnect.tsx`, `IntegrationCard.tsx`, `StoreTeam.tsx` в варианте settings). Видят: все авторизованные; вкладка «Команда» — только у состоящих в отделе. Назначение: профиль, пароль, уведомления, пороги, команда.

### Блоки
- Заголовок «Настройки», подпись «Управление аккаунтом и настройками».
- Вкладки с иконками: «Личные данные» (User), «Команда» (Users), «Интеграции» (Bell), «Статусы» (AlertTriangle); активная подчёркнута, у вкладки с несохранёнными изменениями — «*».
- Общая панель-карточка с контентом вкладки; внизу кнопка «Сохранить эту вкладку» / «Сохранение…» (отключена, если нет изменений) и подсказка «Сохраняются только изменённые поля этой вкладки. * — есть несохранённые изменения.»

### Вкладка «Личные данные»
- «Личные данные» / «Управление профилем»; поля «Имя» (плейсхолдер «Ваше имя»), «Email» (плейсхолдер name@example.com); примечание «Этот email используется для входа. Отдельный адрес для уведомлений можно указать во вкладке «Интеграции».»
- «Безопасность аккаунта»: пояснение, поля «Текущий пароль», «Новый пароль», «Повторите новый пароль», примечание про 8 символов / 72 байта.
- Ошибки-тосты: «Новые пароли не совпадают.», «Пароль: минимум 8 символов, максимум 72 байта UTF-8.», успех «Изменения вкладки сохранены!».

### Вкладка «Интеграции»
- Карточка Telegram: «Telegram · помощник для обхода», подключение бота (`TelegramConnect`), чекбокс «Личные уведомления в Telegram», примечание «Выключение уведомлений сохраняет доступ к боту. Для применения нажмите «Сохранить».»
- «Расписание уведомлений»: «Время Минска (Europe/Minsk). Используется для Telegram и email.», поля-времени «Ежедневный отчёт Срочно» и «Раннее предупреждение Внимание».

### Вкладка «Статусы»

## Проблемы текущего UI, видимые из кода

1. **Скрытые жесты десктопной таблицы.** Одиночный клик копирует ячейку, двойной — редактирует; подсказка только в title. Клик-копирование перехватывает выделение текста и мешает обычному чтению таблицы. — `src/components/products/ProductTableEnhanced.tsx:298,354,408`
2. **Кнопка «Печать» печатает не печать.** Под иконкой принтера вызывается экспорт выделенного в Excel (`exportProductsToExcel`). Пользователь ожидает распечатку. — `src/pages/dashboard.tsx:438-442,602-610`
3. **Разный словарь статусов на мобильном и десктопе.** Плитки мобильной карточки: «Активные»/«Архив»/«Брак» (`product-status-actions.ts:17-22`), кнопки десктопа: «В Активные»/«В Архив»/«В Брак» (`dashboard.tsx:569-599`), бейджи: «Активен»/«Архив»/«Брак». Три варианта одного действия.
4. **Разные шаблоны деструктивных действий.** Мобильное удаление — отложенное с отменой (6 с, `MobileProductList.tsx:32,146-171`); десктопное одиночное и массовое удаление — мгновенные, без подтверждения и без отмены (`dashboard.tsx:298-306,328-339`). Плюс часть подтверждений — нативные `window.confirm`/`window.prompt` (`StoreTeam.tsx:42,78`, `UsersTab.tsx:111`, `BackupTab.tsx:143,172`, `LogsTab.tsx:78`, `DepartmentsTab.tsx:78-84`) вместо модалок приложения.
5. **Ошибки таблицы через window.alert.** Единственное место с alert при неуспешном инлайн-сохранении, тогда как всё приложение тостит. — `src/components/products/ProductTableEnhanced.tsx:217`
6. **Дубли статистики и счётчиков на дашборде.** Число в шапке + строка «Всего/Скоро истекает/Просрочено» + подвал «Выделено N из N» и «Всего: N товаров» — четыре места с пересекающимися числами на одном экране. — `src/pages/dashboard.tsx:493-496,743-749`
7. **Два разных пустых состояния одного списка.** Страница: «Измените фильтры или добавьте товар, чтобы начать.» vs таблица: «Измените фильтры или добавьте товары» — визуально конкурируют на десктопе. — `src/pages/dashboard.tsx:649-650` vs `src/components/products/ProductTableEnhanced.tsx:737-738`
8. **Импорт Excel спрятан.** Кнопка «Импорт из Excel» находится внутри `<details>` «Добавить несколько товаров из файла» внутри модалки добавления — triple nesting, низкая обнаруживаемость ключевой функции. — `src/pages/dashboard.tsx:760-774`
9. **Английский UI на /admin/issues.** «Issue Log», «Timestamp», «Level», «Message», «Meta», «No logs found» — прямое нарушение инварианта русского интерфейса; страница дублирует вкладку «Журнал» poorer-версией и нигде не связана навигацией. — `src/pages/admin/issues.tsx:17`, `src/components/admin/issues/IssueTable.tsx:35-45`
10. **Английские значения ролей в админке.** В таблице пользователей бейдж показывает сырые «USER»/«ADMIN» и кнопки «Сделать USER»/«Сделать ADMIN», тогда как мобильные карточки тех же данных — русские «Админ»/«Сотрудник». — `src/components/admin/UsersTab.tsx:286,302` vs `229`
11. **Непоследовательные правила пароля.** Настройки и создание сотрудника — мин. 8 символов/72 байта (`settings.tsx:156-157`, `StoreTeam.tsx:6`), сброс пароля в админке — мин. 6 (`UsersTab.tsx:139,401,426`), создание аккаунта в админке — 8 (`UsersTab.tsx:200`). Пользователь видит разные требования в зависимости от пути.
12. **Зелёная кнопка в админке нарушает дизайн-систему.** «Сохранить каталог» — `bg-emerald-600`, при том что DESIGN.md прямо запрещает зелёный как основной акцент; там же смешаны тон синего: жёсткий `#1554b5` (signin, UsersTab, BackupTab), `blue-600/700` в Tailwind и `primary-action`. — `src/components/CatalogImport.tsx:31`, `src/pages/auth/signin.tsx:173`, `src/components/admin/BackupTab.tsx:342`
13. **Тёмная тема мертва, но таскается по всему коду.** Классы `dark:` присутствуют почти в каждом файле, хотя тёмная тема исключена редизайном — шум в стилях, риск рассинхрона. — например `src/components/products/ProductTableEnhanced.tsx:681-738`, `src/components/admin/BackupTab.tsx`
14. **Кладбище модальных паттернов и дубли иконок.** Вкладки «Каталог» и «Копии данных» админки используют одну иконку Database (`src/components/admin/index.tsx:23-24`); вкладка «Статусы» настроек использует AlertTriangle — ту же семантику, что «Брак» в списках (`src/pages/settings.tsx:77`); ручное время бэкапа и включение тумблером живут в двух несвязанных контролах (`BackupTab.tsx:294-348`). Плотность иконок-действий в строке таблицы — 5 подряд маленьких кнопок без подписей (`ProductTableEnhanced.tsx:545-615`).

Дополнительно (не в счёт минимальных 10): в мобильной карточке строка «Количество не указано» добавляет шум каждой записи (`MobileProductList.tsx:322`); поиск молча сбрасывает результат скана при вводе текста (`dashboard.tsx:507`); `admin/issues` — единственный экран без role-guard в коде страницы (`src/pages/admin/issues.tsx`); регистрация названа «Создать аккаунт», но фактически создаёт отдел и делает пользователя руководителем (`src/pages/auth/register.tsx:141-146,221`).

Чего в коде нет (для честности макета): отдельного лендинга; тёмной темы как режима; страниц «архив» или «брак» как отдельных роутов (архив/брак — только фильтр состояния на дашборде); пагинации и фильтров на /admin/issues; подтверждения перед десктопным удалением; экранных редакторов отдела для сотрудника (только просмотр).
