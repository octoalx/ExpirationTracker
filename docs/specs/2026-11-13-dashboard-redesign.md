## Что изменится для вас

Экран «Товары» станет таким, каким вы его выбрали на макетах 13.11: сверху три крупные цифры — просрочено, скоро истекает, всего, и нажатие на цифру сразу оставляет в списке только эти товары. Товары со срочным сроком будут стоять первыми отдельной группой, а не размазаны по общему списку. На телефоне список будет разбит на группы «Просрочено / Сегодня / Срочно / Внимание» с крупной датой. Кнопки переименованы по смыслу: «Печать», которая на самом деле выгружала Excel, станет «Экспорт в Excel»; удаление везде будет с отменой, а не мгновенное.

## Problem

Макеты трёх направлений сделаны 13.11 (`redesign/mockups/`), разбор — `redesign/DIRECTIONS.md`, референсы — `redesign/REFS-VISUAL.md`, инвентарь экранов и 14 проблем текущего UI — `redesign/INVENTORY.md`. Владелец выбрал 13.11 вариант «Пульт» (десктоп: сводка сверху служит фильтром, срочное — первой группой таблицы) и телефонный список из направления «Полка» (группы по сроку, крупная дата).

Сегодня экран не умеет следующего:

- срочное смешано со всем списком, порядок по умолчанию — «сначала новые» (`dashboard.tsx:192-193`); чтобы увидеть просрочку, нужно переключить фильтр;
- число записей показано в четырёх местах: в шапке, строкой «Всего / Скоро / Просрочено», в подвале таблицы «Всего: N товаров» и «Выделено N из N» (`dashboard.tsx:493-496,743-749`);
- кнопка с иконкой принтера «Печать» фактически запускает экспорт в Excel (`dashboard.tsx:438-442,602-610`);
- на телефоне жёсткий порядок «сначала новые», а смена фильтра на «Скоро» сама подставляет сортировку по сроку (`src/lib/days-left.ts:24-29`) — в одной и той же карточке два разных порядка;
- удаление на телефоне с отменой и отложенное (`MobileProductList.tsx:32,146-171`), на десктопе мгновенное и без подтверждения (`dashboard.tsx:298-306,328-339`).

## Acceptance criteria

- AC1 — На `/dashboard` при ширине 1440 есть сводка из трёх ячеек с числами «Просрочено», «Скоро истекает», «Всего»; нажатие на «Просрочено» оставляет в таблице только просроченные записи, нажатие на «Всего» снимает фильтр. Проверяется браузерным проходом: снимок + число строк в таблице до и после нажатия.
- AC2 — Счётчик числа записей в DOM дашборда встречается только в сводке и в панели выделения («Выбрано: N»); заголовок страницы без числа, подвал таблицы без «Всего: N товаров».
- AC3 — Показываемые записи идут в порядке FEFO (самый близкий срок первым, записи без срока — в конце); первая группа таблицы на десктопе — срочные и просроченные с заголовком «Скорее истекают», полная группа — «Все товары». Групп не видно, когда в них нет записей.
- AC4 — Порядок и разбивка не зависят от страницы пагинации: запись с самым близким сроком всегда в первой строке первой страницы, независимо от выбранного фильтра состояния. Проверяется тестом на функции группировки и браузерным проходом с `На странице: 10`.
- AC5 — На телефоне список разбит на группы «Просрочено», «Сегодня», «Срочно», «Внимание», «В норме», «Без срока»; дата в строке набрана кеглем не меньше 20 px и табличными цифрами; ручной селект сортировки на телефоне убран.
- AC6 — На десктопе и на телефоне удаление одной записи и массовое удаление работают по одному шаблону: запись исчезает из списка сразу, внизу появляется тост «Товар удалён» с кнопкой «Отменить» на 6 секунд; никаких `window.confirm`/`prompt`/`alert` в дашборде.
- AC7 — Кнопка «Печать» отсутствует; на её месте «Экспорт в Excel», выгружающий текущий фильтр, и та же кнопка в панели выделения выгружает только выбранные строки.
- AC8 — В интерфейсе дашборда один словарь статусов: бейдж записи «Просрочен / Срочно · N дн. / Внимание · N дн. / Осталось N дн.», статус «Активен / Архив / Брак», действия «В Активные / В Архив / В Брак».
- AC9 — `npm run typecheck`, `npm run test:app`, `npm run check:context`, `npm run test:harness` зелёные; `npm run build` собирается.

## Contract change

Ярлыки действий над статусом были частью проверяемого контракта: `tests/mobile-status-actions.test.ts` ждал «Брак / Активные / Архив», теперь ждёт «В Брак / В Активные / В Архив» (`src/lib/product-status-actions.ts:17-22`). Причина: AC8 требует одного словаря действий, а старые ярлыки были не действием, а существительным; рядом с «Изменить» они читались как список статусов, а не как команда. Замена — то же поведение, другой текст. Второе: `tests/mobile-product-sort.test.ts` больше не проверяет ручной селект сортировки на телефоне (AC5 убирает селект, порядок задают группы), проверка перенесена на `sortProductsForMobile` и группировку.

## Risks and invariants

- Date boundaries and timezone: группировка использует существующие пороги из `src/lib/expiry-calendar.ts` и `src/lib/inventory-settings.ts`; «сегодня» считается по тем же правилам, что и сейчас. Тест покрывает вчера/сегодня/завтра и конец месяца.
- Пагинация: группировка применяется к уже отфильтрованному по правам и фильтрам набору и не меняет число записей; проверяется сравнением счётчиков до/после.
- Удаление: отложенное удаление на телефоне уже использует `src/lib/pending-delete.ts` — десктоп переводится на тот же модуль, а не на новый.
- Мобильный режим: строка списка не меньше 64 px, кнопка сканера остаётся первой целью; таб-бар 60 px не перекрывается.
- API и права не меняются: данные те же, фильтрация по отделу остаётся в обработчике как сейчас.
