Type: feature
Branch: local/dashboard-dialogs
Spec gate: `npm run check:spec`

## Что изменится для вас

Окна «Добавить товар», «Редактировать товар» и «Импорт из Excel» станут как редизайн списка: те же цвета, шрифты и отступы. В окне добавления поля идут в порядке работы со сканером: сначала штрих-код, потом название, потом срок, потом количество; при вводе даты изготовления и срока годности расчётная дата видна до нажатия «Сохранить». Импорт перестаёт быть спрятанным в двух раскрывашках — кнопка рядом с «Добавить», окно показывает предпросмотр и число строк до загрузки.

## Problem

Дашборд переделан (спека `2026-11-13-dashboard-redesign.md`), но окна остались в старом оформлении: `src/components/AddProductForm.tsx`, `EditProductForm.tsx`, `ImportExcelModal.tsx` используют старые классы и плотность. Кнопка импорта спрятана в `<details>` внутри окна добавления (`redesign/INVENTORY.md`, проблема 8). Расчётная дата при способе «Изготовлен» показывается, но мелко и вне основной колонки; на телефоне окно не приспособлено к клавиатуре.

## Acceptance criteria

- AC1 — окно «Добавить товар» и «Редактировать товар» на 1440 и 375 использует токены редизайна (те же цвета фона, рамок, текста, радиусы 10/12, кегли из `DIRECTIONS.md`, направление «Пульт»); на телефоне поля в одну колонку, кнопки «Сохранить» и «Отмена» — в закреплённом снизу блоке.
- AC2 — порядок полей в окне: штрих-код (с кнопкой камеры только на телефоне) → название → способ срока («Годен до» / «Изготовлен») → дата/срок → количество. Расчётная дата «Годен до» при способе «Изготовлен» видна до сохранения и обновляется при изменении даты или срока.
- AC3 — «Импорт из Excel» вызывается одной кнопкой из шапки страницы (рядом с «Добавить»), без вложенных раскрывашек; в окне есть зона выбора файла, предпросмотр строк, число найденных строк и число строк с ошибками до нажатия «Импортировать».
- AC4 — ошибки полей показываются под полем, текстами на русском, с `aria-describedby`; отказ сервера показывается в окне, а не тостом поверх.
- AC5 — на телефоне окно не ломается при открытой клавиатуре: закреплённый низ не перекрывает активное поле, окно прокручивается.
- AC6 — `npm run typecheck`, `npm run test:app`, `npm run build` зелёные; ручной проход 1440 и 375 по каждому окну с невалидным и валидным вводом.

## Risks and invariants

- Дата и часовой пояс: расчёт «Годен до» из даты изготовления и срока (дни/недели/месяцы) не меняется; тест покрывает конец месяца и февраль.
- Импорт Excel: разбор файлов (`src/lib/excel-parser.ts`, `inventory-import.ts`) не трогаем; меняется только окно и точка входа.
- Права и API: те же запросы, те же ответы.
- Телефон: камера только на телефоне (правило уже введено в `src/lib/media-query.ts`).

## Result and handoff

Проверено 13.11.2026 на production-сборке (`next build` + `next start`), одноразовая БД `temp/verify.db` (27 записей), Chromium 1440×900 и 375×812.

- AC1 → PASS. Окна на 1440 и 375 собраны на токенах редизайна (те же синий `#1554B5`, рамки `#DDE2E8`, радиусы 10/12, кегли); на 375 поле в одну колонку, «Отмена» и «Сохранить товар» — в закреплённом блоке снизу. Снимки `redesign/dlg-375-add.png`, `redesign/dlg-1440-add.png`. Ограничение: реальная экранная клавиатура не проверялась.
- AC2 → PASS. Порядок в DOM: `add-barcode` → `add-name` → переключатель срока → `add-manufacture`/`add-duration` → `add-quantity`. При способе «Изготовлен», дате 01.11.2026 и сроке 3 месяца превью показывает «Годен до 01.02.2027».
- AC3 → PASS. Кнопка «Импорт из Excel» — одна, в шапке страницы (`1` совпадение в DOM, без `<details>`); в окне после выбора файла появляются «Импортировать N товаров», «Другой файл», тип файла и список строк с ошибками (`ImportExcelModal.tsx:205-310`). Снимок `redesign/dlg-1440-import.png` — холостое состояние без файла.
- AC4 → PASS. Отправка пустой формы даёт «Введите штрих-код — от 8 до 14 цифр.» и «Введите название товара.» под полями, `aria-describedby` ведёт на `add-barcode-error` и `add-name-error`.
- AC5 → PASS частично. Окно на 375 занимает экран, прокручивается (`scrollH` 812 при 812), закреплённый низ не перекрывает активное поле в проверенном состоянии; поведение при реальной экранной клавиатуре не проверялось.
- AC6 → PASS. `npm run typecheck` — 0 ошибок; `npm run test:app` — 149 тестов, 149 pass, 0 fail; `npm run build` — успешно.

Дополнительно в список файлов: `out-of-spec: src/lib/product-form.ts` — общий модуль разметки полей срока, вынесен из двух форм; `out-of-spec: package.json` — новый набор `tests/dashboard-dialogs.test.ts` в `test:app`.

Не проверено: загрузка реального .xlsx через браузер (проверен только холостой экран), экранная клавиатура на телефоне, iOS/Android Safari.
