# Настройки на дизайн-системе редизайна

Status: APPROVED
Owner approval: Алекс, 13.11.2026, в чате: «Вливай в мейн и дорабатывай все остальное» (этап остальных экранов)
Type: feature
Branch: local/settings-redesign
Spec gate: `npm run check:spec`

## Что изменится для вас

«Настройки» станут такими же, как остальные экраны: та же палитра, шрифты, отступы и карточки. Четыре вкладки останутся на месте, поля и тексты — те же.

## Problem

`/settings` не переделан: другие классы, другие радиусы и плотность, вкладка «Статусы» использует красные и янтарные градиентные карточки, которых больше нигде нет. Рядом с новым дашбордом, «Обходом» и «Статистикой» страница выглядит чужой.

## Acceptance criteria

- AC1 — все четыре вкладки на 1440 и 375 собраны на токенах редизайна; между «Настройками» и остальными экранами нет визуального шва (ширина контента, заголовки, отступы секций, карточки, радиусы).
- AC2 — вкладки читаются как один ряд с иконками и подчёркиванием активной; признак несохранённых изменений («*») и подсказка внизу сохраняются.
- AC3 — вкладка «Статусы»: вместо градиентных карточек — две ячейки того же вида, что сводка дашборда (подпись, число, подсказка), с красным и янтарным акцентом только в тексте и метке; значения порогов приходят из настроек отдела, а не из хардкода.
- AC4 — вкладка «Интеграции»: Telegram-карточка, расписание и SMTP в одном стиле; кнопка «Тестовое письмо» — не розовая, а вторичная того же вида, что остальные кнопки действий.
- AC5 — на 375 нет горизонтального скролла, поля в одну колонку, цели нажатия ≥ 44 px, нижняя навигация не перекрывает последнюю кнопку.
- AC6 — `npm run typecheck`, `npm run test:app`, `npm run build` зелёные; ручной проход 1440 и 375 по всем вкладкам, снимки в `redesign/`.

## Out of scope

- Логика профиля, пароля, интеграций и порогов не меняется.
- Вкладка «Команда» использует уже переделанный `StoreTeam`; сам компонент не переписывается.
- `/admin` — следующий этап.
- Новые `dark:`-классы не добавляются; тёмная тема не включается.

none

## Risks and invariants

- Несохранённые изменения и пометка «*»: механизм черновиков (`src/lib/settings-draft.ts`) не меняется.
- Пароль: правило «минимум 8 символов, максимум 72 байта UTF-8» остаётся текстом и проверкой.
- Telegram и SMTP: запросы те же, токены и пароли не логируются.
- Пороги отдела читаются теми же API, что и раньше.

## Verification plan

- AC1, AC2, AC5 → снимки 1440/375 всех вкладок, замер `scrollWidth`, минимальной высоты цели
- AC3 → снимок вкладки «Статусы», значения порогов сверены с ответом API
- AC4 → снимок вкладки «Интеграции», кнопка «Тестовое письмо» в одном стиле с остальными
- AC6 → команды

## Result and handoff

Проверено 13.11.2026 на production-сборке, одноразовая БД, Chromium 1440×900 и 375×812.

- AC1 → PASS. Все четыре вкладки на токенах редизайна; снимки `redesign/settings-1440-{personal,team,integrations,statuses}.png` и те же на 375.
- AC2 → PASS. Вкладки одним рядом с иконками, активная подчёркнута; пометка «*» и подсказка внизу сохранены (`settings.tsx`).
- AC3 → PASS. «Статусы»: две ячейки вида сводки (подпись, крупное число, подпись снизу), красный и янтарный только в точке и числе; значения 3 и 7 приходят из API настроек отдела (сверено с ответом), не из хардкода. Снимок `redesign/settings-1440-statuses.png`.
- AC4 → PASS. «Интеграции»: Telegram, расписание и SMTP в одном стиле; «Тестовое письмо» — вторичная кнопка того же вида, что остальные действия. Снимки `redesign/settings-1440-integrations.png`, `-open.png`.
- AC5 → PASS. На 375 `scrollWidth` = 375 на всех вкладках, поля в одну колонку, минимальная высота цели — 44 px, нижняя навигация не перекрывает последнюю кнопку (зазор 48 px при прокрутке до конца).
- AC6 → PASS. `npm run typecheck` — 0 ошибок; `npm run test:app` — 163 теста, 163 pass, 0 fail; `npm run build` — успешно.

Ограничения: на десктопе поля внутри вкладки «Команда» остались 32 px (общий компонент `StoreTeam` не переписывался, вне задачи); экранная клавиатура телефона не проверялась; ADMIN без отдела в браузере не открывался — тексты не менялись.
